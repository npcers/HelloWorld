# ReadFlow 产品设计方案与实施路线图

## 一、 项目愿景与定位

**ReadFlow** 是一款运行在 Android 移动端的**极简离线稍后读、纯净排版阅读与多格式导出工具**。

### 核心痛点与定位差异化
1. **微信文章防丢失（避险存档）**：解决微信生态内文章易 404/被清理的问题，实现一键完整离线本地固化。
2. **零服务器成本与终极隐私**：无需注册第三方云服务，所有解析、数据存储与资源下载 100% 运行在用户本地手机端。
3. **摆脱昂贵订阅制**：替代 Cubox、Readwise 等昂贵工具，面向注重数据自主权的技术极客与阅读爱好者。
4. **知识库桥梁**：打通移动端信息摄入到 PC 端个人第二大脑（Obsidian、Logseq、Notion 等）的阻碍。

---

## 二、 核心技术痛点与解决策略

### 1. 微信公众号排版与图片防盗链
* **痛点**：微信图片包含 `Referer` 防盗链机制，且正文普遍采用 `data-src` 懒加载，常规爬取会导致图片挂掉或导出全白。
* **对策**：
  * 解析时遍历 DOM，将 `data-src` 转换为合法 `src`。
  * 离线下载图片到应用私有目录，在本地生成映射，将正文图片路径彻底本地化（`file://` 或相对路径）。

### 2. 极致的无感采集体验
* **系统分享面板（Share Target）**：注册 Android 原生 `ACTION_SEND` Intent 接收器，微信/浏览器中点击“分享到 ReadFlow”，后台静默拉取并提示存入。
* **剪贴板前台感知**：应用打开或唤醒时检测剪贴板中的链接（如匹配 `mp.weixin.qq.com` 或通用 URL），弹出轻量浮层提示一键解析。

### 3. 播客（Podcast）轻量化处理
* **避坑**：初期不上庞大的端侧 ASR（语音转文字）模型。
* **MVP 方案**：提取单集 **Shownotes（节目简介/时间轴/引用链接）**，实现格式清洗、Markdown 化与链接沉淀。

## 三、 三套演进架构方案

### 方案 A：极致极简流 —— 纯本地 Markdown / PDF 抓取箱（MVP 首选）
* **架构**：100% 本地端无服务器架构。
* **技术栈**：
  * **UI**：Android Jetpack Compose（现代、流畅的响应式界面）。
  * **正文提取**：`readability4j`（Mozilla Readability 算法的 Java/Kotlin 实现），自动抽离正文并滤除杂质。
  * **HTML 转 Markdown**：`flexmark-java`。
  * **本地数据库**：Android Room (SQLite)。
  * **导出能力**：导出 `.md`（带本地图片 zip 打包）及离线 PDF/长图。

### 方案 B：自托管 / WebDAV 增强流 —— 笔记知识库生态联动
* **架构**：在方案 A 基础上，支持开放存储协议。
* **功能**：
  * 支持 WebDAV 同步（坚果云、群晖 NAS、Nextcloud、阿里云盘等）。
  * 支持直接将解析后的 Markdown 文件提交到用户的 GitHub / Gitee 私有仓库，实现移动采集、PC 端无缝阅读（如直接进 Obsidian 库）。

### 方案 C：混合代理提取流 —— 复杂动态网页兜底
* **架构**：处理高强度 JS 渲染或严格风控的网页。
* **实现**：本地唤起轻量不可见 Headless Android WebView，等待完整执行前端 JS 后注入提取脚本扒取完整 DOM。

## 四、 MVP 首发版本核心功能清单（阶段��）

1. **接收入口**：
   * Android 系统原生分享菜单接收链接。
   * App 内部手动粘贴 URL 解析。
2. **清洗处理**：
   * 自动抽取：标题、发布日期、作者、纯净正文 HTML、封面图。
   * 图片本地持久化缓存，规避防盗链失效。
3. **离线阅读**：
   * 沉浸式本地阅读器（纯净无干扰排版、字体字号调节、图片轻点放大）。
4. **纯净导出**：
   * `[复制为 Markdown]`（代码块保留、图片链接规范）。
   * `[导出为长图 / PDF]`（干净排版、无水印、支持打印与分享）。
